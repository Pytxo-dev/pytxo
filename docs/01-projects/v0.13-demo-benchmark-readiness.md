# v0.13 demo and benchmark readiness

Release-candidate evidence for the first-run branch after the v0.13.0 Desktop
readiness release.

## Demo

`apps/demo-video` contains an editable 63-second, 1920×1080 Remotion
composition. Its eight-scene story is:

```text
pressure → control layer → mission → Race → Blast → Operations → approval → result
```

The product scenes reuse the deterministic v0.13.0 Flow, Operations, and
Approvals captures. The default render is silent and needs no external key.
`VOICEOVER.md` supplies scene-bounded lines, delivery direction,
pronunciation, filenames, and an optional ElevenLabs generation script. Audio
and rendered output stay ignored.

Verified locally:

- composition: 1,890 frames / 63 seconds / 30 FPS / 1920×1080;
- TypeScript and Remotion composition discovery pass;
- eight representative frames pass a full-frame contact-sheet inspection;
- H.264/AAC MP4 render: 63.061 seconds, 8,766,397 bytes.

The current managed Windows sandbox blocks Playwright's worker fork with
`spawn EPERM`, including when pointed at installed Chrome. The unchanged
Desktop and web suites remain covered by the handoff's 53/53 and 6/6 passing
runs; this pass independently revalidated the Rust workspace, Desktop native
artifact, web production build, Remotion composition, and benchmark scripts.

## Real-repository proof

The new benchmark scripts operate on tracked production source instead of the
tiny fixture:

- `real-repo-signal.ps1`: 185 files, 1,228,911→211,277 scaffold bytes,
  **82.8% weighted reduction**, 86.25% median;
- `real-repo-control-plane.ps1`: five real-path tasks, one declared overlap,
  two waves, zero same-wave path collisions, five successful agents, zero
  primary-checkout changes, and 16.677 seconds of local isolated echo-run
  overhead.

These results do not measure model quality, billable tokens, competitor
performance, review quality, or task success. Raw JSON stays beside the
scripts under `tooling/benchmarks/results/`.

## Defect found by the real workload

The first Windows execution terminated with `0xC00000FD`. Copy-layer
preparation excluded only its own destination, so concurrent destinations
under `.pytxo/worktrees` could recursively copy sibling agent layers.

The fix excludes the shared workspace subtree while preserving other
`.pytxo` files, adds Windows and generic regressions, and makes status report
the effective `overlay` / `projfs-sparse-copy-v2` backend instead of the
configured `worktree` intent.

Scope remains Orbit/default isolation inside one execution domain. Permission
profiles, Race scheduling, approve-to-flush, and cleanup semantics are
unchanged.

## Release boundary

The source is ready for a review and patch release after the complete
repository gates pass. External completion remains separate: merge this
branch, cut the patch, and deploy current `main` to production. The live web
deployment was still pinned to v0.11.0 at the start of this pass.
