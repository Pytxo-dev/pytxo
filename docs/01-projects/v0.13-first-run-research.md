# v0.13.0 and first-run docs research

Primary-source snapshot (2026-07-30) for website docs drift, the v0.13.0 release impact, and actionable next steps. Sources are git SHAs, PR/release URLs, repo files, live `pytxo.com`, and Vercel deployment metadata — not secondary blogs.

**Verdict in one line:** Product/npm/GitHub Releases are on **0.13.0**; first-run public docs live only on unmerged `docs/first-run-sharpen`; live Vercel production is still pinned to a **v0.11.0** web deploy.

Merging alone does not update live docs while production stays on the v0.11.0 web tree. Deploying `main` without the sharpen merge would still leave install.mdx at 0.8.0 and no First mission page.

### Product / Desktop / CLI (from PR #20 + notes)

https://github.com/Pytxo-dev/pytxo/pull/20 — *release: v0.13.0 Desktop readiness and claim integrity* (merged 2026-07-30):

- **Exact-run Stop** — orchestration refuses stale run IDs; Ops confirmation names run / workspace / domain; cancelled is terminal (`pytxo-orchestrate` + Desktop Ops; tests in `stop_exact.rs`).
- **DPI / zoom matrix** — simulated 100/125/150% device scale × 90/100/110% zoom at 860×560; ordered `build:native` embeds current frontend.
- **Marketing product truth** — mission-led homepage, real Ops/Flow/Approvals captures, `verify:product-assets` rejects duplicate aliases.
- **Plans honesty** — capability-gated Pro/Max/Ultra copy; Focus/Ops framing instead of topology-as-primary.
- **Native Desktop evidence** — `docs/_attachments/desktop-2/native/*` from Tauri release binary.

CLI impact in the same release tree is mostly orchestration/stop lifecycle and related store transitions; Mission Loop itself landed in **v0.12.0** (`RELEASE.md` / `distribution/release-notes/v0.12.0.md`). Sharpen-branch CLI copy changes (Blast/Race plain language before codenames) are **not** in the v0.13.0 tag.

### Claim integrity and intentional non-goals

`PLAN.md` Desktop readiness / product-truth / Plans passes (1–6) are all checked complete and repeatedly list **DO NOT TOUCH**:

- Blast Shield flush / Race Shield claims / permission-profile policy / execution-domain semantics
- Billing checkout / Clerk / plan slug entitlement wiring (Plans pass softens *copy* only)
- Desktop route IA; legacy `desktop_shell_v1`; physical DPI multiplication
- Invented Cloud/Ultra availability; 3D topology as primary Desktop surface

Release notes explicitly keep open: physical Windows 100%/150% DPI and macOS Retina QA; legacy DeckWorkspace chunk advisory; Orbit still human approve-to-apply.

### Release process — Windows-first / Actions billing

PR #21 https://github.com/Pytxo-dev/pytxo/pull/21 adds one paragraph to `distribution/release-notes/v0.13.0.md` (same pattern as v0.12.0):

> GitHub Actions billing is currently blocking the multi-OS Release matrix; this tag ships a **fresh Windows CLI** (and Desktop when built locally) plus interim non-Windows CLI mirrors from `v0.12.0` so `npm i -g pytxo@0.13.0` still resolves.

That honesty is on GitHub Releases and the distribution notes on `main`, but **not** yet on live install docs (still 0.8.0) or live `/download` (still 0.11.0).

## 3. Sensible next steps (evidence-grounded)

Ordered by how directly they close measured gaps. No invented roadmap items beyond repo/`gh` evidence.

1. **Open a PR for `docs/first-run-sharpen` and merge to `main`.**
   One commit, already pushed; closes install 0.8.0↔0.13.0 drift on the Fumadocs tree, adds First mission, collision fixture + rewritten Getting Started. Follow-up in the same PR or a tiny follow-on: bump `desktop-setup.mdx` off **v0.8.0** (still stale on the branch).

2. **Deploy `apps/web` to Vercel production from post-merge `main`.**
   Production is still `563b1c8` / `release/v0.11.0` (`dpl_DzWY9oAnL1H4etSFqdSiTmGch11s`). Until that moves, live `/download` stays 0.11.0, docs stay pre–first-run, and homepage can still say “topology” despite `main` already fixing Focus/Ops footer copy. Merge without deploy leaves live site unchanged.

3. **Treat website/docs honesty as a release gate alongside npm/GitHub.**
   On `main` alone: `site.ts` = 0.13.0 while `install.mdx` = 0.8.0. Pre-marketing gate #5 in [[pytxo-improvement-research]] already requires cross-platform matrix **or** clear Windows-first labeling — release notes have the label; public Getting Started on `main` and live site do not yet.

4. **Restore or keep labeling the Actions multi-OS matrix.**
   Notes admit non-Windows CLI assets may be mirrors of v0.12.0. Open packaging issues remain: [#1 Homebrew](https://github.com/Pytxo-dev/pytxo/issues/1), [#2 winget](https://github.com/Pytxo-dev/pytxo/issues/2), [#5 npm Windows ARM64](https://github.com/Pytxo-dev/pytxo/issues/5) (also [#3](https://github.com/Pytxo-dev/pytxo/issues/3) Docusaurus search — likely stale vs Fumadocs; [#4](https://github.com/Pytxo-dev/pytxo/issues/4) TUI log tail).

5. **Dogfood Mission Loop Phase 1 (Phase 77).**
   [[pytxo-improvement-research]] still names Mission Loop Phase 1 as current build focus. [[mission-loop-dogfood]] matrix cells are empty; collision demo on the sharpen branch is the scripted Race/Blast proof path once merged — run dry-run + echo smoke from `tooling/demos/collision`, then fill dogfood rows without inventing “collisions avoided.”

6. **Close residual Desktop QA called out by v0.13.0 notes / backlog — not new features.**
   Physical Windows 100%/150% and macOS Retina still open ([[desktop-ui-improvement-backlog]], release notes). `PLAN.md` passes 1–6 are done; do not reopen Blast/Race/billing/3D primary without a new ADR/plan. Low priority: DeckWorkspace chunk advisory / whether 3D remains a Desktop 2 goal.

7. **Do not ramp paid marketing until live site matches claim-integrity `main` + first-run docs.**
   Market-ready research marks homepage/Plans honesty **verified in-repo** (2026-07-29); live production has not absorbed that verification yet.

Unmerged branches vs `main` (local): only `docs/first-run-sharpen` (and its remote). `chore/v0.13.0-notes-billing` is already merged via PR #21.
