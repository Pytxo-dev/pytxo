# v1.3 audit — inconsistencies and weaknesses

Matt asked for every inconsistency and weakness across architecture, vision,
UI/UX and backend. Each item says what was found, the evidence, and whether
v1.3 fixed it or deferred it (with the reason). Sizes measured 2026-10-10 on
branch `mbcz/v1.3-land`.

## Fixed in v1.3

| Area | Finding | Fix |
|---|---|---|
| Product | The sold layer (parallel agents) is free and crowded; the gate at the end of the run had no surface outside Pytxo-run fleets | `pytxo land` for branches from any tool; receipts; repositioned copy ([[ADR-0042-landing-gate-and-receipts]]) |
| CLI | macOS/Linux users could install the CLI but not Review or Apply; docs said "no `pytxo apply`" in five places | `pytxo review`, `pytxo apply` (digest-bound), docs corrected |
| Website | FAQ answers clipped: the accordion pinned its inner block to a stale measured height and used Base UI `data-open` selectors on a Radix primitive | Content sizes to its text; Radix `data-state` selectors; a Playwright test that fails on the old component and passes on the fix (1440 and 390 px) |
| Website | The proof band said OpenCode/Antigravity "causes are fixed" (2 Oct) while the 10 Oct live run showed Antigravity still auto-denying its tool permission | Proof uses the 10 Oct released-build run and Pybench; both agents labelled beta/experimental on the site and in Desktop |
| Website | Five product sentences ("agent hypervisor for your repository", "Local commit layer", "many coding agents, one verified change") across metadata, hero, footer | One line: "The landing layer for coding agents"; H1 unchanged |
| Website | Evidence lived on a marketing page; Signal and run records mixed | `/docs/evidence` (index, Pybench, live runs, Signal Core); `/evidence` redirects |
| Website | Clerk sign-in was live (clerk.pytxo.com) but the header had no sign-in; the account page showed `max agents 3` and Routing internals to everyone | Header Sign in/Account; account page shows perks, connected tools, shared receipts; Routing and org panels only when relevant |
| Website | `/plans` described "Cloud / Teams in configured deployments" | Free, Free account, Team (planned, no price) |
| Desktop | Settings → Account said sign-in was "paused"; a Tier row showed `core` with "concurrent agent limits" while Desktop allows 8 workers | Working PKCE sign-in, perks, sign-out; Tier row removed |
| Desktop | `SetupStepSignIn.svelte` and `auth_open_sign_in` opened a page that could not return to Desktop; neither was reachable from the wizard | Both deleted |
| Accounts | Two half-built account paths (disabled bearer-in-URL callback, Routing-only PKCE bridge) and no general account | One PKCE account flow for CLI (loopback) and Desktop (deep link); hashed codes and credentials in Link (migration 020) |
| Benchmarks | Scattered scripts and dated one-off JSON; no repeatable product benchmark | Pybench (`pytxo bench`): land, overhead, signal suites with machine identity |
| Gate performance | First gate version merged in a worktree per run: 2–3× `git merge` | In-memory `merge-tree`/`commit-tree`; worktrees only for checks |

## Deferred, with reasons

| Area | Finding | Evidence | Why deferred / next step |
|---|---|---|---|
| Architecture | Experimental Routing lives inside the core orchestration crate | `routed_*.rs` = 13,641 of 28,845 lines in `pytxo-orchestrate`; Link Routing = 3,715 of 9,004 lines; `pytxo-core/src/routing.rs` 1,635 lines | Moving it behind a feature-gated crate touches the run contract and Desktop IPC; too risky for a launch release. 1.4: extract `pytxo-routing`, off by default |
| Architecture | `flow.rs` (247 KB) and orchestrate `lib.rs` (187 KB) are single files | File sizes | Split by responsibility (draft, dispatch, review/apply) in 1.4 with no behavior change |
| Backend | Ultra wallet, arbitrage ledger and managed transport ([[ADR-0009-ultra-managed-metering]]) ship in core with no product behind them | `pytxo-core/src/billing` 1,098 lines; tiers note still lists Ultra $99 | Pricing decision (strategy §9) is "no prices until Team exists". Mark ADR-0009 superseded by a pricing ADR when Team is designed; tiers note marked historical now |
| Backend | Link Postgres paths for accounts are untested against a real database | No local Postgres/Docker daemon; memory store contract test covers handlers | Add a CI job with a Postgres service for Link before deploying migration 020 |
| Backend | Paddle and Dodo commerce adapters for a product with no prices | `commerce.rs`, `paddle.rs`, `dodo.rs` | Keep dark (fails closed); activate only with Team |
| Desktop | Legacy Deck shell, 3D topology and its state still ship in the bundle behind a dev flag | ~2,250 lines across `dashboard/`, `topology/`, `shell/`, `workspace/`, `panels/`; `App.svelte` 616 lines | Removal needs a native regression pass; 1.4 cleanup |
| Desktop | Windows only | Release assets | CLI parity in 1.3 covers macOS/Linux for the core loop; build Desktop elsewhere when users ask |
| Receipts | Unsigned | Receipt format | DSSE with a per-install key in 1.4; digest already makes edits evident |
| Agents | Antigravity headless denies its own tool permission; OpenCode default model cannot use tools on the test machine | 10 Oct live run | Adapter work per vendor; labelled experimental until a live run passes |
| Process | Running notes are very large | `CHECKPOINT.md` 510 KB, `RELEASE_READINESS.md` 196 KB, `RELEASE_PLAN.md` 90 KB | Archive pre-October sections to `docs/_archive/` in a docs-only change; agents read the top entry only |
| Vision | The vault still describes Pytxo as a "hypervisor" with a production-effect commit layer as north star | [[product-vision]] | Kept as architecture vocabulary; the public sentence is the landing layer, which is the commit layer's first shipped surface. Updated [[positioning]] and AGENTS.md |
