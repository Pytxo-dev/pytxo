**Pytxo Desktop** is an optional control UI for planning, supervising, and reviewing agent work. It is not a wall of terminal panes.

Download installers from [pytxo.com/download](https://pytxo.com/download).

## At a glance

| Panel | What you see |
|-------|----------------|
| Ops | Needs you, Running rows, path locks, spend, and attention state |
| Missions | Past work, **New mission**, and a selected mission’s Plan / Live / Review |
| Approvals | Pending Galaxy requests (with domain label), then Apply or Discard |
| Workspaces | One or more project folders under one coordinated run |
| Agents | Installed CLIs and vendor-owned session readiness; MCP hub is CLI/IDE (`pytxo-mcp`) |
| Settings | Appearance (Void / Light, teal), Providers, and shortcuts |
| Project paths | Roots, read-only badges, permission tiers |
| Fleet runs | Cross-repo fleet status via CLI today; Desktop fleet panel coming later |

Older hashes such as `#/flow`, `#/integrations`, `#/runs`, `#/topology-focus`, and `#/run-review` still open the matching Missions or Agents view.

## New mission

**New mission** is the mission-to-plan workflow. Enter an outcome, select an execution domain, and
review the resulting tasks, waves, path claims, agent CLI assignments, permissions, isolation, cost
estimates, warnings, and blockers before **Run**.

Desktop sends intent; the orchestrator enforces Signal Core, Race Shield, Blast Shield,
permission ceilings, and execution-domain validation before a plan can run.
There is no quick-run path: every mission must be previewed first.

Open a running or finished mission to switch **Plan**, **Live**, and **Review**. **Apply** lands accepted isolated changes; it is not a separate Runs or Focus destination.

## Pytxo Voice

Voice captures speech and turns the transcript into an editable mission. Transcription runs
locally with an on-demand model. Raw microphone audio remains in bounded memory and
is cleared on completion, cancellation, device loss, or shutdown; it is never stored in Pytxo's
catalog, logs, events, or diagnostics.

Voice can create mission text only. It cannot navigate Desktop, approve actions, stop runs, or
dispatch work automatically.

## Design principles

- Void or Light, with a calm teal accent
- Structural views over raw terminal walls
- No direct filesystem access from the UI; all data comes through local IPC
- Plan preview before dispatch
- Keyboard-accessible capture, navigation, and decisions

## Structural topology

During an active run, the mission **Live** pane shows:

- **Nodes:** files and modules from the Signal Core structural graph
- **Edges:** import relationships between them
- **Token savings:** per-run saved-token totals when Signal Core samples exist

This is a structural map of how agent edits touch your code, not a wall of terminal text.

## What it is not

- Not a replacement for your IDE
- Not the primary place to read agent stdout (logs are supporting panels)

## Requirements

Install the Pytxo CLI first. Desktop talks to the same orchestrator and SQLite stores as `pytxo run`.
