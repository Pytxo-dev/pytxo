---
title: GitHub Action
description: Check every agent pull request together with the other open agent pull requests, with one line of GitHub Actions.
---

Add `.github/workflows/pytxo.yml`:

```yaml
name: Pytxo
on: pull_request
permissions:
  contents: read
  pull-requests: write
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: Pytxo-dev/pytxo/actions/land@v2
```

No inputs, no labels, no other steps.

## What it does

On each pull request event:

1. **Is this an agent pull request?** It is when its branch matches `claude/*`, `codex/*`, `copilot/*`, `cursor/*`, `devin/*`, `jules/*` or `agent/*`, or when an agent account opened it (Copilot, Claude, Cursor, Devin or Jules). Anything else ends the job with a note in the job summary.
2. **Which pull requests go together?** This one plus the other open agent pull requests into the same base branch, oldest first, at most 10. Drafts count. If this is the only one, there is nothing to combine.
3. **The check.** It fetches those branches and runs `npx pytxo check` on them, which merges them in a throwaway worktree and runs the test command it finds in the base branch.
4. **The verdict.** It posts one comment on the pull request and updates it on every run. A blocked, stale or failed check fails the job, so you can make it a required check.

## Inputs

All optional.

| Input | Default | Description |
|---|---|---|
| `check` | found in the base branch | Test command, such as `npm ci && npm test` |
| `branches` | the agent patterns above | Branch patterns that count as agent pull requests, space-separated |
| `comment` | `"true"` | `"false"` keeps the verdict in the job summary only |
| `token` | `github.token` | Token that lists pull requests and comments |
| `license` | none | Pytxo Pro license key for private repositories. Not needed today |
| `version` | the Action's release | Pytxo CLI version from npm |

The `decision` output is `ready`, `blocked`, `stale`, `error` or `skipped`.

## Your tests need their tools

The check runs your own test command, so the runner needs whatever your tests need. GitHub's `ubuntu-latest` has Node.js, and the Action needs Node.js 18 or newer for `npx`. Put your usual setup steps, such as `actions/setup-python` or `astral-sh/setup-uv`, before the Pytxo step.

## Security

- It runs on `pull_request` only. On `pull_request_target` it refuses to run, because that event would run pull-request code with a write token.
- The token is only in the steps that list pull requests and comment. The step that runs your tests does not get it, and the Action's own checkout does not store it in `.git/config`. If you add your own `actions/checkout` before Pytxo, set `persist-credentials: false`.
- A fork's pull request never joins another pull request's run, so fork code never runs with that run's token. A fork's own run gets GitHub's read-only token, so its verdict goes to the job summary.
- `permissions` above is all it needs: `contents: read` to fetch the branches, `pull-requests: write` to comment. Without `pull-requests: write` the verdict goes to the job summary instead.
- It never pushes, merges or changes a branch.
