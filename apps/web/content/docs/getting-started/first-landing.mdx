---
title: First landing in 5 minutes
description: Install the CLI and get a pytxo land decision on two agent branches in your own repository.
---

> **Pytxo 2.0:** `npx pytxo` with no arguments finds agent branches like these and the test command on its own; start with the [Quickstart](/docs/getting-started/quickstart). This walkthrough was measured with 1.3, and its `pytxo land` commands still work in 2.0.

This guide goes from installing the CLI to a landing decision on your own repository. Every time on this page was measured on Windows 11 with Pytxo 1.3.0, or a 1.3.1 build where the text says so, on [lukeed/mri](https://github.com/lukeed/mri), a small npm package whose test suite runs 84 assertions, using one branch from Claude Code and one from Codex.

You need Node.js 18 or newer, Git, and a repository with at least two agent branches. Any tool that leaves each agent's work on its own branch will do: Claude Code, Codex, Orca, Conductor or plain `git worktree`. Make sure each agent's changes are committed; Pytxo lands commits, not uncommitted files.

## 1. Install

```bash
npm i -g pytxo
pytxo --version
```

npm 12 and pnpm 10 skip install scripts by default, so `npm i -g` installs only the launcher and prints a warning about pytxo's `postinstall`, which you can ignore. Your first `pytxo` command downloads the native binary and checks it against the release's SHA-256 list: 4.3 seconds after an npm 12 install on 2026-10-22, and 19.4 and 27.8 seconds in earlier pnpm and `--ignore-scripts` runs. Later commands start in under a second. npm 11 and older run the download during `npm i -g` instead (22.7 and 29.9 seconds in two runs).

## 2. Check the branches together

Check out the branch you want to land into, then run this from your repository. Pytxo checks the branches you name against that branch:

```bash
pytxo land claude:claude/double-dash codex:codex/empty-value --check "npm install && npm test" --per-input
```

Use your own branch names. The `claude:` and `codex:` prefixes are labels for `--verbose` output and the receipt; leave them off if you prefer.

The check runs in a fresh worktree where nothing is installed, so a Node project has to install its dependencies in the check. Use `npm ci` instead of `npm install` if the repository has a lockfile. With `--check "npm test"` alone, every check failed on `'bundt' is not recognized`, which is mri's build tool missing, not a problem with the branches. If you leave out `--check`, Pytxo 2.0 runs the test command it finds in your project files, installing dependencies first for a `package.json` that has any.

`--per-input` also runs the check on each branch alone, which tells a broken check apart from a broken combination. With 1.3 this command took 73.1 seconds: 24.7 and 6.9 seconds for the branches alone and 22.3 seconds for the combination, mostly `npm install`. The output is the verdict in three lines, starting with `READY`. Add `--verbose` to see what was found, every check run and the receipt's path as well.

Ready means no conflict and every combined check passed. Nothing changed yet: your branch and working tree are as they were.

## 3. If the decision is BLOCKED

In a second run, Claude Code renamed the helper `toVal` to `assign`, while Codex made negated flags call `toVal`. Each branch passed alone. Together they failed. The `BLOCKED` verdict says so, and its `why` line quotes the first error. `--verbose` adds every check run; a 1.3.1 build printed:

```text
checks
  input:claude/rename-helper   pass           20.8s  npm install && npm test
  input:codex/negated-flags-v1 pass           5.4s  npm install && npm test
  combined                     FAIL exit 1    16.0s  npm install && npm test
      ReferenceError: toVal is not defined

! Every input passed its checks alone. The combined change failed.

decision  BLOCKED
```

Fix the failure on one of the branches, then run the same command again. Here the fix was to rebase the Codex branch onto the Claude branch and rename the call in one commit; the next run took 68.9 seconds and was ready. `pytxo receipts show <id>` prints the last 40 lines of each check.

## 4. Land it

Add `--apply` to the same command:

```bash
pytxo land claude:claude/rename-helper codex:codex/negated-flags --check "npm install && npm test" --per-input --apply
```

`--apply` runs the checks again and moves the checked-out branch only if the result is still ready and that branch has not moved. With 1.3 it took 57.0 seconds and the decision was LANDED: one merge commit per agent branch on top of the checked-out branch. Because `--apply` lands only a ready result, you can pass it on the first run.

## 5. Keep the receipt

```bash
pytxo receipts
```

Every decision, blocked ones included, has a receipt in `.git/pytxo/receipts`; `pytxo receipts show <id>` prints one and checks its digest. `pytxo receipts share <id>`, which publishes a page with counts and outcomes after `pytxo login`, is only in source builds with the default `full` feature, not in the npm binary.

## The measured total

| Step | Time |
|---|---|
| `npm i -g pytxo` | 22.7 s |
| `pytxo --version` | 0.3 s |
| `pytxo land … --check "npm install && npm test" --per-input` | 73.1 s |
| **Install to decision** | **96.1 s** |

These are command times only; reading the output is extra. npm's package cache was already warm: a cold `npm install` of mri took 40.5 seconds on the same machine.
