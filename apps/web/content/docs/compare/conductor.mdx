---
title: Pytxo and Conductor
description: One job split across agents with one reviewed Apply, compared with Conductor's workspace-per-task model.
---

[Conductor](https://www.conductor.build/docs) runs Claude Code, Codex, Cursor and OpenCode in parallel. Each task gets its own workspace: a Git worktree with its own branch, files, terminal, diff and review path, usually ending in a pull request. As of 2 October 2026 Conductor also offers cloud workspaces and shared, multiplayer workspaces, and its [changelog](https://www.conductor.build/changelog) notes that merging from Conductor is blocked when the pull request changed on GitHub.

Pytxo starts from one request instead of one task per agent. It plans the request into tasks, gives each task to an agent you chose, keeps tasks that share a file from running at the same time, runs your checks on every task and on the combined change, and applies exactly the files you reviewed.

## Practical differences

| | Conductor | Pytxo |
|---|-----------|-------|
| Unit of work | One workspace and branch per task | One request, planned into tasks that own their files |
| Agents | Claude Code, Codex, Cursor, OpenCode | Codex, Claude Code, Cursor Agent, OpenCode, Antigravity |
| Shared files | Separate branches; overlaps surface when you merge | A task that shares a file waits for the task that owns it |
| Checks | Your project's CI and PR checks | Pytxo runs your commands on each task and on the combined change |
| Review | Each workspace's diff, then a pull request | One combined change, with the agent behind each file |
| Landing | Push, PR and merge | Apply writes the reviewed files to your checkout; refused if the project changed |
| Where it runs | macOS app and cloud workspaces | Windows Desktop, locally; CLI on macOS and Linux |

## Choose Conductor when

- Each task is separate and the branch and pull request are your review workflow.
- You want cloud workspaces, shared sessions with teammates, or setup scripts and ports per workspace.
- You work on macOS.

## Choose Pytxo when

- Several agents should finish one job together without you merging their branches.
- You want checks run on the exact combined change before anything lands.
- You work on Windows, or want everything to stay on your machine.

Pytxo does not replace pull requests. After Apply, you continue with your normal Git workflow.
