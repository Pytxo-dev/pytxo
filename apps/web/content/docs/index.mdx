Pytxo is the landing layer for coding agents. Split one request across the agent CLIs you already use (Codex, Claude Code and Cursor Agent; OpenCode and Antigravity in beta), or bring branches from any agent tool. Pytxo checks the combined change, shows exactly what will land, refuses if anything moved, and leaves a receipt. Keep your editor and your existing agent accounts.

**Start here:** [Install Pytxo](/docs/getting-started/install), then [set up Desktop](/docs/getting-started/desktop-setup). Already have agent branches? Get a [first landing in 5 minutes](/docs/getting-started/first-landing) from the CLI.

## Which version are you using?

The public download is **v1.3.5**. If your installed Desktop looks different from these guides, update it from [Download](/download).

Desktop is available for **Windows x64**. The CLI runs on Windows, macOS and Linux and, since 1.3, covers Review, Apply and `pytxo land`.

## Your first workflow

1. **Describe a small change.** Name the files and the result you want.
2. **Check the plan.** See which agent runs each task, the files it owns, and the test commands.
3. **Run and review.** Inspect the prepared changes and their check results.
4. **Apply when ready.** Write the reviewed changes to your repository, or discard them.

Pytxo does not require an account; a free one adds [sharing perks](/docs/getting-started/account). Your agent's sign-in and usage costs are separate.

## What the protection covers

Reviewed Apply controls changes to **one repository**. It does not control every command, network request, or file access an agent can make. The run's enforcement receipt shows which protections were active. Passing tests mean those tests passed, not that every behavior is correct.

Learn more in [What is Pytxo?](/docs/concepts/what-is-pytxo).
