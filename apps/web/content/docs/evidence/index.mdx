Every number Pytxo publishes comes from a record you can download, with the build it ran on and its limits. A benchmark, a recorded run and a byte measurement answer different questions, so they are kept apart.

| Record | Answers | Does not answer |
|---|---|---|
| [The demo](/evidence/demo-blocked-2.0.0-2026-10-30.json) | What `npx pytxo demo` prints on a local 2.0 candidate build, cause included, and how long it took in three timed runs on a busy laptop (8.5 to 8.9 s) | Anything about real projects: Pybench wrote both branches, no agent did |
| [Pybench](/docs/evidence/pybench) | What per-branch CI would put on main compared with what the check decides, in known situations; what the check costs | How often those situations happen in real projects |
| [First use](/docs/evidence/first-use) (1.x) | How long a new user takes from `npm i -g pytxo` to a landing decision on a real repository with two live agents' branches, and where they go wrong | How long it takes on other repositories, languages or machines |
| [Live runs](/docs/evidence/live-runs) (1.x) | Whether a released build completes a real multi-agent job with live vendor CLIs, Review, a stale refusal and Apply | Speed, reliability rate, or whether the resulting code is correct |
| [Signal Core](/docs/evidence/signal-core) (1.x) | How much smaller the structural scaffold is than the source, in bytes | Model tokens, cost, or task success |

## Rules we hold ourselves to

- A number is quoted only from its record file, with the date and build.
- Failed and refused attempts stay published next to the successful ones.
- Passing checks are reported as "these commands passed on these exact files", never as "the code is correct".
- Synthetic benchmarks say they are synthetic.
- Agents that have not completed a live end-to-end run on a release are labelled beta.

Run Pybench yourself with `pytxo bench`, and compare with the [published board](/bench).
