# Pytxo v1.2.2

Pytxo v1.2.2 is a multi-agent Windows Desktop beta candidate. Give several
coding-agent CLIs one request, review their combined changes, and decide what
enters your project. Pytxo runs configured checks and binds Apply to the exact
reviewed package. If the project changes after review, Apply refuses.

These are prepared release notes, updated October 3, 2026, not a release
announcement. The current local candidate is unsigned and has not been
published. Final-artifact native acceptance, clean install/upgrade, multi-DPI
acceptance, updated hosted CI, signing and publication approval remain gates.
Current evidence and artifact identities are in `RELEASE_READINESS.md`.

The recorded October 2 run used six tasks across five vendors, with four
workers running concurrently followed by two ordered steps. Seven files were
prepared by Codex, Claude Code and Cursor Agent. OpenCode and Antigravity
exited without preparing changes. The combined checks and stale-safe Apply
passed; that earlier run is not proof of the final candidate or of every
requested feature being implemented.

## [added]

- Per-task CLI assignments: Codex, Claude Code, Cursor Agent, OpenCode and
  Antigravity can share a reviewed plan. The local worker cap is eight; tasks
  with shared files run in order.
- A fleet board in Work shows the recorded agent, recent output, owned paths,
  task state and an expandable activity timeline.
- Review opens on a line diff with recorded per-file ownership. Before & after
  remains available for exact-content inspection.

## [changed]

- New work exposes the team before planning. Setup uses compact agent rows,
  readiness rechecks and the agents' own marks.
- Plain-language states across Work, Review, History, Approvals and onboarding;
  native caption buttons and a quick start in the terminal shell.
- Combined-candidate verification records the included source inventory, exact
  commands, and enforcement receipt. Per-task checks remain distinct evidence.
- Desktop provides scoped mission templates, complete editable task prompts,
  visible ownership and dependencies, and an agent readiness recheck.
- Reusing a draft restores its workspace and available CLI, then requires a new
  plan. Missing workspaces or CLIs require an explicit replacement selection.
- Private and public CLI publication now starts from an empty staging directory
  and requires exactly the five supported binaries plus `SHA256SUMS.txt`.
- Desktop mirroring now starts from an empty staging directory and uses an exact
  inventory for both signed updater releases and unsigned installer-only
  releases.
- Desktop checks a branch-backed signed updater channel before the GitHub
  Latest-release fallback. Signed releases advance the stable manifest only
  after publishing its referenced asset; unsigned releases preserve the last
  valid signed channel.
- Release uploads fail when an expected file glob does not match.

## [fixed]

- Line diffs preserve CRLF and final-newline changes instead of displaying
  byte-different files as unchanged.
- List view uses readable task requests while retaining recorded task IDs.
  The readable Output view joins corroborated terminal wraps; Raw text preserves
  the original recorded payloads and event boundaries.
- Fleet output drains after a worker settles, continues beyond the first
  2,000 events, retries failed reads and cannot borrow another run's output.
- Completed workers with no configured checks are not labelled "Checks passed".
  A worker that prepared no files is identified as "No changes".
- Workers settle as soon as they exit. Recorded output stays one line per event
  and is not written twice.
- OpenCode readiness requires stored provider credentials; shell-only keys do
  not establish worker readiness.
- Low-concurrency planning retains every approved task.
- Workers receive the approved file ownership, dependencies and checks alongside
  their task text. Outside-scope edits still prevent package preparation.
- Windows Codex missions preserve quoted, multiline and Unicode prompts through
  the installed launcher using its supported stdin interface. Generated task
  guidance stays on one line for the other Windows adapters.
- Work and History expose the recorded package-preparation failure. History no
  longer labels a refused package as an attempted Apply or borrows another run's
  rollback evidence while the selected run loads.
- Windows PTY launches retain the intended local workspace instead of letting
  CMD fall back from an extended path to the Windows directory. Unsupported
  UNC/device shell working directories report an explicit error.
- Agent details resolve the stored per-agent receipt and distinguish project
  root identity from isolation. Switching runs cannot borrow prior evidence,
  and a run in its starting phase remains stoppable.
- Stop includes tracked verification processes and prevents later dispatch.
  Cancellation is saved before termination, and child reaping can proceed
  without a held registry lock. Failed termination retains process evidence.
- Stale source, verification mutation, and incomplete event evidence block
  Apply eligibility. Refresh preserves intended effects and operator changes
  while rerunning candidate verification without blocking the Desktop UI.
- Required approval audit records are persisted before decisions are published.
- Verification and Apply resolve original task permissions by runtime actor
  identity. Later grants cannot widen that original cap; missing or inconsistent
  saved receipts are refused instead of falling back to a broader run profile.
- Cloud planning requires explicit opt-in; inherited provider keys no longer
  select it, and explicit local planner settings take precedence.
- Context reflects composed dependency output and the current retry workspace.
  Fresh retry directories omit deleted source; fidelity respects profile caps.
- Context output rejects unsafe labels and redirected generated paths, and
  atomic replacement preserves outside hardlink aliases. Windows UNC storage
  paths retain their absolute roots and original characters.
- Release staging verifies checksum coverage and actual binary bytes before
  publication, including the manual Windows MSI.
- Removed obsolete tracked release files that could overwrite newly built
  Windows CLI and checksum assets during public Desktop mirroring.
- Ignored the repository-root `dist/` directory so local release outputs cannot
  accidentally become source-controlled publication inputs again.
- Replaced the abandoned ICO encoder and its vulnerable legacy image/request
  dependency chain with a small, validated PNG-in-ICO encoder. Release tooling
  now audits with zero known vulnerabilities.

## Scope

Reviewed Apply remains limited to Orbit and Galaxy, one execution domain, and
one repository root. Pytxo Desktop remains Windows-first. Filesystem and network
controls may be advisory; this release does not establish an OS-wide sandbox,
universal process containment, or a comparative productivity improvement.
