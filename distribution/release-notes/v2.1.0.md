# Pytxo v2.1.0

When agent branches pass alone and fail together, Pytxo now says why: which
branch renamed or removed a name, which branch still uses it and where, and
which agent has to fix it. With three or more branches it proves which pair
fails, so the others are not blocked. It still calls no model and sends
nothing anywhere.

These are prepared release notes, updated October 30, 2026, not a release
announcement.

## [added]

- **The cause of a failure together.** When every branch passes alone and
  the combination fails, Pytxo looks for a definition one branch renamed or
  removed that another branch's new code still uses, with git and
  tree-sitter. When the failing output confirms it, the verdict says so:

  ```
  BLOCKED  claude/rename-price and codex/add-discount pass npm test alone but fail together.
  why      claude/rename-price renamed price to unitPrice; codex/add-discount still uses price (src/discount.js:1).
  next     rebase codex/add-discount onto claude/rename-price and use unitPrice, then run npx pytxo again.
  ```

  A name left only in strings, comments or docs is not a use, a field that
  shares a renamed method's name is not one either, and a branch that
  defines the name itself is not blamed. When the output does not confirm
  it, the why line stays the error and a note names the possible cause.
  Other branches that use the same name are named with it.
- **The culprit pair.** With three or more branches and a cause, Pytxo runs
  the failing check on the pair alone and then on the other branches
  without it, at most two extra runs: "claude/rename-price and
  codex/add-discount fail together; agent/readme passes without them." In
  CI, the Action then fails only the pull requests of the branches behind
  the failure. The extra runs never start when they would end past the
  hook's or the Action's time limit.
- **A fix prompt for the agent that has to change.** The PR comment shows it
  under "Fix prompt for `<branch>`", `--json` adds `verdict.cause` and
  `verdict.fix_prompt`, and `pytxo hook --block` hands it to the agent whose
  worktree the hook runs in. Each of the two agents hears its own prompt
  once, from the same check. The fix runs in the agent you already use.
- **Copilot's pull requests in the Action.** A pull request from Copilot's
  coding agent, which GitHub holds until a person approves its run, joins
  the other agent pull requests' check at the newest commit someone let run,
  and the comment names that commit. It needs `actions: read` in the
  workflow's permissions, which the setup leaves out unless you add it.

## [changed]

- **The why line is the error the check printed.** It prefers an error or
  exception name, then a traceback, assert or compiler diagnostic, then a
  failing test file, and never a count such as `ℹ fail 1` or Go's package
  summary. It also reads error lines above the output's last 40, so one
  failed package of a Go module, or a Rust error above its warnings, still
  shows.
- **Paths read as in your checkout.** A stack frame or compiler error from
  the check reads `src/discount.js:4:10`, not the temporary worktree's path,
  in receipts, why lines, fix prompts and PR comments.
- **A hook waits for another agent's check.** When two agents stop at the
  same moment in one repository, the second hook waits for the first one's
  check, up to its own time limit, and answers from it; 2.0's stayed quiet.
  Each hook answers in its own form, so without `--block` both agents'
  sessions see a verdict with a confirmed cause once.
- **A branch name means the branch.** A tag, or a file such as `FETCH_HEAD`,
  named like an agent branch no longer changes the commit that is checked,
  in the CLI and in the Action.
- **Receipts say which branches a pair or rest run merged,** in the run's
  scope, such as `pair:1,2`. 2.0 still reads and verifies 2.1's receipts,
  and 2.1 verifies 2.0's.
- **Pro licensing, still switched off, uses Dodo Payments license keys.**
  Once Pro is on, a private repository's run sends only its `license` key
  to Dodo Payments after the 14-day trial. Only a definite "not valid"
  refuses it; when Dodo does not answer, the check runs with a warning.

## Scope

The check (`crates/pytxo-land`), pytxo-signal's name reading, the `pytxo`
command, the agent hooks and the GitHub Action. Pytxo Desktop is unchanged
apart from its version. Pytxo sends nothing anywhere; the Action talks to
GitHub, and to Dodo Payments only once Pro is switched on.

## Install

```bash
npx pytxo demo
npx pytxo --version
```

The first `pytxo` command downloads the binary and checks it against the
release's `SHA256SUMS.txt`. To keep it on your PATH: `npm i -g pytxo@2.1.0`.
