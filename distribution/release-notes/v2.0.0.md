# Pytxo v2.0.0

Pytxo is one check now: `npx pytxo` merges your agents' branches in a
throwaway worktree, runs your tests on the combined result, and blocks the
merge if it breaks.

These are prepared release notes, updated October 29, 2026, not a release
announcement.

## [added]

- **`pytxo` with no arguments runs the check.** It finds the agent branches
  (`claude/*`, `codex/*`, `copilot/*`, `cursor/*`, `devin/*`, `jules/*`,
  `agent/*` and every branch in a linked worktree, with a commit in the last 14
  days), finds the test command in the target branch, and prints the verdict
  in three lines: what happened, why, and what to do next. With no agent
  branches it prints one line and suggests the demo. Pytxo's own temporary
  worktrees never count as agent branches. `git config pytxo.branches`,
  `pytxo.check`, `pytxo.days` and `pytxo.into` (or `PYTXO_BRANCHES`,
  `PYTXO_CHECK`, `PYTXO_DAYS` and `PYTXO_INTO`) change the defaults.
- **What gets checked.** At most 10 detected agent branches are checked at
  once, newest first. Branches already merged into the target, squash merges
  included, are skipped. Only committed work is checked: a worktree whose
  changes are all uncommitted gets a hint to commit them. Submodules are not
  checked out in the throwaway worktrees. Ctrl+C or SIGTERM stops a check and
  removes its throwaway worktrees; a check that is killed outright leaves them
  in `git worktree list` until the next check removes them.
- **`pytxo demo`.** Builds a throwaway repository where two agent branches
  pass `npm test` alone and fail together, checks them, and deletes it. It
  needs Node.js; `--keep` keeps the repository.
- **`pytxo hook`, a Claude Code plugin and a Codex hook.** The check runs when
  an agent stops. It waits while background agents are still working, and it
  answers when two or more agent branches exist and one of them, the target or
  the test command changed since its last answer. One check runs at a time per
  repository, and other sessions' hooks in that repository stay quiet while it
  runs. The agent's turn ends only when the check does, up to the hook's
  900-second limit; when the check needs longer, it says so and asks you to run
  `npx pytxo` in a terminal. `--block` asks the agent to fix a BLOCKED or FLAKY
  result instead of only reporting it.
- **GitHub Action v2.** `uses: Pytxo-dev/pytxo/actions/land@v2` needs no
  inputs. On an agent pull request (by branch prefix or bot author) it checks
  it together with the other open agent pull requests into the same base and
  keeps one comment on the pull request that started the run. The verdict is
  in the job summary too, which is where it goes when the token cannot
  comment. When no other agent pull request
  is open into that base, the job passes with a note in the job summary. It
  runs on `pull_request` and refuses `pull_request_target`; on any other event
  it does nothing and passes. A fork's pull request never joins another pull
  request's run: it is checked in its own run, with GitHub's read-only token
  and no secrets. Nor does a pull request opened by Copilot or
  `github-actions[bot]`, whose runs GitHub holds for approval: its own run,
  once approved, checks it with the others. A run checks each pull request
  at the commit it saw, so a push after someone approved the run gets a run
  of its own.
- **The Action passes pull requests that are not to blame.** The job fails
  when the pull request it runs for conflicts, fails the tests alone, or is in
  a combination that fails while each passes alone (Pytxo cannot tell which
  one is at fault). When only other pull requests are to blame, the comment
  names them and the job passes. When nothing in the result points at any pull
  request, such as a combined run that timed out, every pull request in the run
  fails. A flaky result passes with a warning.
- **Test output in the Action's comment** is redacted for common secret
  formats and shown as code.
- **The Action's `timeout` input** sets the seconds each test run may take.
- **Pro licensing scaffold**, switched off. Nothing about it runs in this
  release.

## [changed]

- **Plain output.** What was found, every test run with its error lines, the
  receipt's path and a ref to the combined commit move behind `--verbose`;
  `pytxo receipts show <id>` prints the last 40 lines of each run and checks
  the digest. `--json`, `--markdown`, `--apply`, `--per-input` and the exit
  codes (0 ready, 2 blocked, 3 stale) stay.
- **A failed combined check explains itself.** When the combined change fails,
  each branch runs alone to tell a break that only happens together from a
  branch that is already broken, and, if every branch passes alone, the
  combined change runs once more to catch a flaky test. If the combined run
  times out, that is the answer: the branches do not run alone after it, and
  it does not run again. `--per-input` runs the branches alone every time.
- **A usage error now exits 1, not 2** (2 means blocked), and Ctrl+C or
  SIGTERM exits 130.
- **`--apply` lands only a tested result.** When no test command was found,
  it exits 1 and leaves the target unchanged; name one with `--check`.
- **`pytxo land` is now an alias of `pytxo check`.**
- **The target branch.** Branches you name are checked against the branch you
  have checked out, as in 1.x, or against the default branch if the
  checked-out branch is one of them or no branch is checked out. With no
  branches named, the target is the default branch (`origin/HEAD`, else
  `main`, `master` or `trunk`). `--into <branch>`, `git config pytxo.into` or
  `PYTXO_INTO` override both.
- **The released CLI is the check only.** Pytxo Desktop, missions, fleets, the
  terminal dashboard and the other 1.x commands are frozen. They still build
  from source with the default `full` feature; in the npm binary they say they
  are not in this build. The Windows binary drops from about 30 MB to 11 MB.
- **Windows on Arm** installs the x64 binary, which runs under emulation.
- **Moving from Action v1:**
  - `checks` is now `check`.
  - `inputs`, `per-input` and `base` are gone. The Action finds the agent pull
    requests itself and checks them against the pull request's base. Set
    `branches` only for other branch prefixes: it replaces the default
    patterns, so don't move `inputs: "agent/*"` into it.
  - Remove a `version` pinned to 1.x: the v2 Action runs `pytxo check`, which
    1.x does not have.
  - Agent pull requests are found by branch prefix or bot author, not by the
    `agent` label, so drop the label `if:` and the fetch step. Your own
    `actions/checkout` can go unless a step before Pytxo reads your files,
    as `actions/setup-node` with `cache: npm` does; if you keep it, set
    `persist-credentials: false`.
  - Commenting needs `pull-requests: write`.
- **Release tags** are exact versions such as `v2.0.0`.
- **The npm package** has new copy and keywords, and tells the CLI it ran
  through `npx`, so its hints say `npx pytxo`.

## Scope

The check (`crates/pytxo-land`), the `pytxo` command, the npm package, the
GitHub Action and the agent hooks. Pytxo Desktop is unchanged apart from its
version, and checks an installed CLI with `pytxo --version`. Pytxo sends
nothing anywhere.

## Install

```bash
npx pytxo demo
npx pytxo --version
```

The first `pytxo` command downloads the binary and checks it against the
release's `SHA256SUMS.txt`. To keep it on your PATH: `npm i -g pytxo@2.0.0`.
If you installed 1.x with `npm i -g pytxo`, npx runs that copy: update it with
`npm i -g pytxo@latest` or remove it with `npm rm -g pytxo`.
