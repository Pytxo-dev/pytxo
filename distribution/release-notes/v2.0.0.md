# Pytxo v2.0.0

Pytxo is one check now: `npx pytxo` merges your agents' branches in a
throwaway worktree, runs your tests on the combined result, and blocks the
merge if it breaks.

These are prepared release notes, updated October 28, 2026, not a release
announcement.

## [added]

- **`pytxo` with no arguments runs the check.** It finds the agent branches
  (`claude/*`, `codex/*`, `copilot/*`, `cursor/*`, `devin/*`, `jules/*`,
  `agent/*` and every branch in a linked worktree, with a commit in the last 14
  days), finds the test command in the target branch, and prints the verdict
  in three lines: what happened, why, and what to do next. With no agent
  branches it prints one line and suggests the demo. Pytxo's own temporary
  worktrees never count as agent branches. `git config pytxo.branches`,
  `pytxo.check`, `pytxo.days` and `pytxo.into` (or `PYTXO_BRANCHES`,
  `PYTXO_CHECK`, `PYTXO_DAYS` and `PYTXO_INTO`) change the defaults.
- **`pytxo demo`.** Builds a throwaway repository where two agent branches
  pass `npm test` alone and fail together, checks them, and deletes it. It
  needs Node.js; `--keep` keeps the repository.
- **`pytxo hook`, a Claude Code plugin and a Codex hook.** The check runs when
  an agent stops. It waits while background agents are still working and stays
  quiet unless two or more agent branches changed since its last answer. One
  check runs at a time per repository, and other sessions' hooks in that
  repository stay quiet while it runs. The hook finishes inside its time
  limit; when the check needs longer, it says so and asks you to run
  `npx pytxo` in a terminal. `--block` asks the agent to fix a BLOCKED result
  instead of only reporting it.
- **GitHub Action v2.** `uses: Pytxo-dev/pytxo/actions/land@v2` needs no
  inputs. On an agent pull request (by branch prefix or bot author) it checks
  it together with the other open agent pull requests into the same base and
  keeps one comment on the pull request, or writes the job summary when the
  token cannot comment. It runs on `pull_request` and refuses
  `pull_request_target`; on any other event it does nothing and passes. A
  fork's pull request never joins another pull request's run: it is checked in
  its own run, with GitHub's read-only token and no secrets.
- **The Action passes pull requests that are not the cause.** A blocked
  verdict fails the job only when the pull request it runs for fails the tests
  on its own, conflicts with another agent pull request, or breaks the tests
  together with one. When the cause is another pull request, the comment names
  it and the job passes. A flaky result passes with a warning.
- **Test output in the Action's comment** is redacted for common secret
  formats and shown as code.
- **The Action's `timeout` input** sets the seconds each test run may take.
- **Pro licensing scaffold**, switched off. Nothing about it runs in this
  release.

## [changed]

- **Plain output.** Receipts, digests and every check's output move behind
  `--verbose`. `--json`, `--markdown`, `--apply`, `--per-input` and the exit
  codes (0 ready, 2 blocked, 3 stale) stay.
- **A failed combined check explains itself.** When the combined change fails,
  each branch runs alone to tell a break that only happens together from a
  branch that is already broken, and the combined change runs once more to
  catch a flaky test. `--per-input` runs the branches alone every time.
- **`pytxo land` is now an alias of `pytxo check`.**
- **The target branch.** Branches you name are checked against the branch you
  have checked out, as in 1.x, or against the default branch if the
  checked-out branch is one of them or no branch is checked out. With no
  branches named, the target is the default branch (`origin/HEAD`, else
  `main`, `master` or `trunk`). `--into <branch>`, `git config pytxo.into` or
  `PYTXO_INTO` override both.
- **The released CLI is the check only.** Pytxo Desktop, missions, fleets, the
  terminal dashboard and the other 1.x commands are frozen. They still build
  from source with the default `full` feature; in the npm binary they say they
  are not in this build. The Windows binary drops from about 30 MB to 11 MB.
- **Windows on Arm** installs the x64 binary, which runs under emulation.
- **Release tags** are exact versions such as `v2.0.0`.
- **The npm package** has new copy and keywords, and tells the CLI it ran
  through `npx`, so its hints say `npx pytxo`.

## Scope

The check (`crates/pytxo-land`), the `pytxo` command, the npm package, the
GitHub Action and the agent hooks. Pytxo Desktop is unchanged apart from its
version, and checks an installed CLI with `pytxo --version`. Pytxo sends
nothing anywhere.

## Install

```bash
npx pytxo demo
npx pytxo --version
```

The first `pytxo` command downloads the binary and checks it against the
release's `SHA256SUMS.txt`. To keep it on your PATH: `npm i -g pytxo@2.0.0`.
