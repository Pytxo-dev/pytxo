# Pytxo v1.3.0 — Land

Pytxo is now the landing layer for coding agents. Bring branches from any agent
tool, check them as one combined change, and land only what passed. The CLI
covers the whole loop on Windows, macOS and Linux, every decision leaves a
receipt, and Pybench measures what the gate catches.

These are prepared release notes, updated October 10, 2026, not a release
announcement.

## [added]

- **`pytxo land`.** Combine branches from Orca, Conductor, Codex, Claude Code,
  Copilot or your own scripts, run your checks on the combined result (and on
  each branch alone with `--per-input`), and decide: ready, blocked or stale.
  Shared files are mapped to the functions and types each branch changed, so
  two agents editing one function are flagged even when Git merges cleanly.
  Shadow mode by default; `--apply` lands by fast-forward or compare-and-swap
  and refuses if the branch moved. `--markdown` prints a pull-request summary.
- **Receipts.** Every landing decision and every committed reviewed Apply
  writes an in-toto statement to `.git/pytxo/receipts/`.
  `pytxo receipts` lists, shows and checks them.
- **`pytxo review` and `pytxo apply`.** Review a finished run's prepared change
  and apply exactly that package from any platform's CLI. Apply authorizes the
  digest you saw and refuses if the project changed.
- **Pybench (`pytxo bench`).** Offline benchmarks with no model calls: twelve
  landing scenarios comparing per-branch CI with `pytxo land`, gate overhead
  against `git merge`, and Signal Core scaffold size. Reference run: 12/12
  decided as expected; per-branch CI would land a broken main in 4 scenarios
  and `pytxo land` refused all 4; no good change refused. Synthetic by design.
- **Optional Pytxo account with perks.** `pytxo login` (or Desktop Settings →
  Account) signs in through the browser with PKCE. Perks: share a receipt as a
  public page, keep shared receipts across machines, publish Pybench results.
  Nothing local requires an account.
- **GitHub Action.** `actions/land` runs the gate in shadow mode on pull
  requests and writes the summary to the job.
- **Desktop.** Share receipt after Apply; Settings → Account with sign-in and
  sign-out.

## [changed]

- Website and docs lead with the landing layer. Evidence moved into the docs
  (`/docs/evidence`), with Pybench, live runs and Signal Core on their own
  pages; `/bench` shows the reference run and the public board.
- OpenCode and Antigravity are labelled experimental in Desktop and beta on
  the site until they complete a live run on a release.
- Plans: free locally, free account with perks, Team planned with no price.

## [fixed]

- Desktop credentials now persist in the operating system's credential store.
  The keyring library had no platform store enabled, so stored sign-ins did not
  survive (this affected the experimental Routing connection).
- Website FAQ answers no longer cut off after fonts load or the window narrows.
- Desktop Settings no longer says account sign-in is paused, and no longer
  shows an agent tier left over from retired pricing.
- Removed a Desktop sign-in path that opened a page unable to return to the
  app.

## Scope and limits

- `pytxo land` checks what your commands check. Passing checks are evidence,
  not proof that the code is right.
- Landed merge commits are unsigned; sign or squash afterwards if your
  repository requires signed commits.
- Receipts are not signed in this release; their digest shows whether a file
  was edited after it was written.
- Desktop is Windows x64; the CLI runs on Windows, macOS and Linux.
- Account perks need the 1.3 Pytxo services; local features never depend on
  them.

## Install

```bash
npm i -g pytxo@1.3.0
pytxo doctor
pytxo land --help
```
