# Pytxo v1.0.0

Pytxo v1 turns an engineering mission into isolated, conflict-aware agent work
and one reviewable result. This release closes the first-run, provider-readiness,
dependency composition, local-state durability, evidence, and Desktop polish
needed for that loop to work as one product.

## Highlights

- **A real first mission** — Desktop can create a dependency-free approval-risk
  example, open it as an Orbit workspace, and carry its mission directly into
  Flow.
- **Inspectable Flow** — mission planning exposes tasks, path ownership,
  dependencies, conflicts, execution waves, selected agent, dispatch state, and
  terminal verification status before work is applied.
- **Dependency-aware isolation** — successful upstream file changes are
  composed into declared downstream workspaces, including changed files,
  directories, globs, and deletions, without copying unrelated task output.
- **Useful integrations** — Pytxo detects Codex, Claude Code, Cursor Agent,
  OpenCode, Gemini CLI, and Aider; session checks are non-billable and official
  vendor sign-in flows remain owned by each CLI.
- **Safer child environments** — agent PTYs and subprocesses receive a rebuilt
  allowlisted environment plus the explicitly selected provider route, not
  unrelated secrets inherited from Desktop.
- **Durable local control state** — trust and live-process registries now use
  cross-process locks, transactional updates, replace-safe writes, backups, and
  recovery from malformed primary files.
- **Operator-grade Desktop** — clearer onboarding, Integrations and Providers,
  better Flow status and error messages, responsive 960/1280 layouts, and
  proof-oriented Workspaces, Operations, Approvals, and review surfaces.
- **Proof, not a synthetic headline** — reproducible scripts measure Signal
  scaffold bytes across 185 production files and Race/Blast control-plane
  behavior across five deterministic real-repository tasks.
- **Launch kit included** — editable Remotion source, real Desktop captures,
  an ElevenLabs script, and a Screen Studio shot plan ship with the repository.

## Verified release evidence

- Native Pytxo Desktop mission: **3 agents**, **2 waves**, all agents exited 0.
- Downstream test workspace received the upstream implementation output.
- Guided-project regression suite: **4/4 passed** after the mission.
- Signal corpus: **185 production files**, **82.9% weighted scaffold-byte
  reduction**, **0 fallbacks**.
- Control plane: **5/5 tasks**, **1 deliberate overlap**, **0 same-wave path

The Signal figure is a byte-reduction measurement. It is not a token-cost,
model-quality, or task-success claim. The control-plane benchmark makes no

## Authentication boundary

Pytxo does not implement lookalike ChatGPT or Claude login pages and does not
capture vendor passwords, cookies, or token files. ChatGPT subscription access
is represented by the official Codex CLI session; Claude subscription access by
the official Claude Code session. Direct API keys are configured separately and
are never returned to the Desktop webview.

Pytxo Cloud account login remains disabled until the flow uses PKCE and
cryptographically verifies issuer, audience, signature, state, and nonce.

## Distribution note

GitHub-hosted runners are currently account/billing-blocked before any workflow
step starts. v1.0.0 therefore ships fresh **Windows x64 CLI and Desktop**
artifacts through the local release fallback. macOS and Linux CLI assets on the
tag are explicit compatibility mirrors from v0.13.0 and still report that
version; they do not contain the v1 orchestration changes. No v1 macOS or Linux
Desktop build is claimed.

The Windows installer is a manual-download channel when no Tauri signing key is
available; an unsigned build does not update `latest.json`.

## Upgrade notes
