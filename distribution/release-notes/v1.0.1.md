# Pytxo v1.0.1

Pytxo Desktop is now a quieter instrument: fewer destinations, calmer chrome,
and captions that match the shipping UI. This is a **presentation** release. It
does not include atomic apply, the planner rewrite, or the domain-scoped read
model reserved for 1.1.0.

## Highlights

- **Nav is Ops, Missions, Approvals, Workspaces, Agents, Settings** — Focus and
  Runs are no longer separate destinations.
- **New mission composer** with **Plan / Live / Review** on a selected mission.
  Buttons are New mission, Build plan, Run, Apply, Discard, and Stop.
- **Calm Chroma** — teal accent, Void and Light only. Spectrum, Nebula, and
  Terminal themes are gone.
- **Deep-link aliases still work** — `#/flow`, `#/integrations`, `#/runs`,
  `#/topology-focus`, and `#/run-review` open the matching Missions or Agents
  view. Canonical hashes are written on later navigation.
- **Product screenshots recaptured** for docs, the website, and demo stills.
  Filenames `flow-*` and `integrations-*` are unchanged.

## Not in this cut

- Atomic apply
- Planner quality rewrite
- Domain-scoped read model
- Homepage layout recut beyond alts and a few operator words
- Onboarding wizard replay (`ONBOARDING_VERSION` remains `1.0.0`)

```bash
npm i -g pytxo@1.0.1
pytxo doctor
```

- https://github.com/Pytxo-dev/pytxo-releases/releases/tag/v1.0.1

## Authentication boundary

Unchanged from v1.0.0. Pytxo does not implement lookalike vendor login pages
and does not capture vendor passwords, cookies, or token files. Direct API keys
are configured separately and are never returned to the Desktop webview.

## Distribution note

v1.0.1 prefers the GitHub Actions **Release** workflow (all platforms, npm, and
the public mirror). If hosted runners are still account/billing-blocked, only a
fresh **Windows x64 CLI and Desktop** ship from this tag. Do not treat older
macOS or Linux binaries as 1.0.1. A mirrored binary keeps its embedded original
version.

The Windows installer is a manual-download channel when no Tauri signing key is
available; an unsigned build does not update `latest.json`.

## Upgrade notes

- Existing Desktop users keep their current onboarding state.
- Orbit still requires human approval before applying changes.
- Vendor sessions and direct API credentials remain separate.
- Existing `pytxo.toml` task and agent configuration remains compatible.
