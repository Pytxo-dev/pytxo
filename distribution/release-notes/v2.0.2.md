# Pytxo v2.0.2

A first run now shows what Pytxo is doing and what to do next. `npx pytxo demo`
lands a pile of four agent branches and leaves two out with the reason, a
verdict gives each branch its own line when only some can land, every test run
is named while it runs, and a repository with no agent branch is told which
branches it could check.

## [added]

- **A line for each branch.** With three or more branches where only some can
  land, the verdict lists them all: `landed`, or `left out` with why.

  ```text
  LANDED   2 of 4 branches are on main now.
  left out claude/rename-price  renamed price to unitPrice, which codex/add-discount still uses
  left out codex/add-discount   uses price, which claude/rename-price renamed to unitPrice (src/discount.js:1)
  landed   copilot/add-tax
  landed   cursor/add-guide
  next     push main when you are ready. Give codex/add-discount's agent its fix prompt, then run npx pytxo again.
  ```

  Without `--apply` the rows read `can land` and a note says how many pass
  together. 2.0.1 put every name into one sentence.
- **`--days <N>`.** It sets the age limit for one run, ahead of `pytxo.days` and
  `PYTXO_DAYS`, and `--days 0` looks at branches of any age. A check that left
  branches out for age says how many in a note under the verdict. Before, it
  said so only when it found nothing to check.
- **Branches that match no pattern.** With no agent branch to check, the
  message names the local branches that are open and recent but match no
  pattern, and gives the command that checks them:

  ```text
  next     feature/tax and fix/rounding are not merged into main: check them together with npx pytxo --into main feature/tax fix/rounding
  ```

  `--json` lists them as `unmatched`. Branches only a remote has are not named:
  in a shared repository those are other people's.
- **Each test run is named as it happens.** On stderr, as it starts and how it
  ended (`together... failed (41.3s)`), and in a terminal a long run gets a mark
  each minute. `--json`, the hooks and Pybench print none of it.

## [changed]

- **The demo lands a pile.** `npx pytxo demo` builds a repository with four
  agent branches and runs `--apply` there: two land, and the two that break
  each other stay out with the cause and a fix prompt for the branch that has
  to change. 2.0.1's demo checked two branches and stopped at BLOCKED.
- **A verdict about conflicts names every branch that conflicts**, grouped by
  what each conflicts with. 2.0.1 named the first one, so a pile of three
  conflicting branches took three runs to read. The pull-request comment names
  them the same way.
- **No test runs when none of the branches merges.** The combination would be
  the target itself, so its tests would say nothing about the branches.
- **`--help`, the crate description and the npm page lead with the current
  pitch**, "Clear your agent PR pile in one command."

## [fixed]

- **Old branches the target already has are not counted** as left out for age.

## Scope

The check (`crates/pytxo-land`), the `pytxo` command, the npm package's page and
the docs. Pytxo Desktop is unchanged apart from its version. On Linux the binary
needs glibc 2.34 or newer. Pytxo sends nothing anywhere.

## Install

```bash
npx pytxo demo
npx pytxo --version
```

The first `pytxo` command downloads the binary and checks it against the
release's `SHA256SUMS.txt`. To keep it on your PATH: `npm i -g pytxo@2.0.2`.
