# Pytxo v2.0.1

`pytxo --apply` now lands what passes. When the whole combination is blocked,
it lands the largest set of branches that passed every test as that exact set
and leaves the others out, each with why and, when it has to change, a fix
prompt for its agent. The target moves to the very commit those runs tested,
and the receipt says what landed and what was left out.

## [added]

- **Partial landing.** With five branches where one renames a function another
  still calls, `--apply` lands the other three and prints:

  ```text
  LANDED   3 of 5 branches are on main now: copilot/add-tax, cursor/readme and devin/add-shipping; claude/rename-price and codex/add-discount are left out.
  ```

  It moves the target by the same fast-forward or compare-and-swap as a full
  landing, so a target that moved is still stale. It exits `2`, so
  `pytxo --apply && git push` stops there: read the verdict before you push.
  Nothing lands after a flaky run, a combined run that timed out, a deadline or
  a `--strict` collision.
- **A note says what would land.** Without `--apply`, a blocked verdict names
  the set `--apply` would land.
- **The receipt says what was left out.** `result` is the landed commit,
  `files_changed` counts its files, and `reasons` gains `landed 2 of 4: a, d
  (rest:1,3 passed every check)` and `left out b: ...`. `pytxo receipts` shows
  `2 of 4 input(s)`. 2.0.0 still verifies these receipts' digests.
- **`/pytxo:land` in the Claude Code plugin.** It runs `pytxo land --apply` and
  relays the verdict and each fix prompt. It never pushes.
- **A check without a test script.** A package.json with no test script gets its
  `build`, `typecheck`, `type-check` or `lint` script checked, and the verdict
  says that is not a test suite. `--apply` won't land on one: it exits `1` until
  you add a test script or name a command with `--check`.

## [changed]

- **The Claude Code `Stop` hook runs in the background**, so a turn no longer
  waits for the tests. Claude gets the verdict at your next message and tells
  you. To wait for it as 2.0.0 did, see the plugin's README. Codex's hook still
  waits.
- **Conflicts name branches.** A receipt's reason reads "conflicts with the
  branches before it", not "the inputs before it".
- **`--help` and the crate description lead with the current pitch**, "Land all
  your agents' branches in one command."
- **The 402 messages match the plans page.** Private receipts and private
  Pybench results belong to an earlier paid tier that is closed to new buyers,
  so the CLI no longer calls them Pro perks or offers an upgrade. Each message
  says what to do instead.

## [fixed]

- **A check's `duration_ms` can't record 0.** The clock started after a check was
  spawned and registered, so a fast check that exited in the meantime read about
  zero, which failed the macOS job. It now starts before the spawn, and a check
  that ran records at least 1 ms.
- **A landing git refuses over your files says so.** It names the files and says
  to commit, stash, move or remove them. Before, a partial landing refused this
  way showed the earlier verdict and told you to run `--apply` again.
- **`merge.autoStash` can't take your edits.** With it set, git could stash
  overlapping local changes during the landing and report success when restoring
  them conflicted. Pytxo now turns it off for that merge, so git refuses instead.
- **A branch stacked under the landed one counts as landed.** Its commits are in
  the landed commit, so the receipt doesn't call it left out and its agent gets
  no fix prompt.
- **Only a Cargo project keeps `target` between runs.** Elsewhere, such as in a
  Maven project, it is the last branch's output.

## Scope

The check (`crates/pytxo-land`), the `pytxo` command, the agent verification
runner's timing, the npm package, the agent hooks and the docs. Pytxo Desktop is
unchanged apart from its version. On Linux the binary needs glibc 2.34 or newer.
Pytxo sends nothing anywhere.

## Install

```bash
npx pytxo demo
npx pytxo --version
```

The first `pytxo` command downloads the binary and checks it against the
release's `SHA256SUMS.txt`. To keep it on your PATH: `npm i -g pytxo@2.0.1`.
