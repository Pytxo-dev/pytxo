# Pytxo v1.1.0

Pytxo v1.1 closes the gap between review and repository mutation. After a
successful Orbit or Galaxy run, Pytxo stores the exact target bytes in an
immutable package. Run Review displays that package, and Apply reads only that
package.

## [added]

- Immutable review packages under `.pytxo/data/reviews/<run-id>/`. Target blobs
  preserve exact bytes for additions and modifications. The manifest records
  add/modify/delete metadata, the base revision, package digest, before and
  after SHA-256 digests, byte counts, and task/agent ownership.
- Apply journals under `.pytxo/data/apply/<run-id>/<attempt-id>/`. Pytxo
  reconciles interrupted attempts before accepting another run or Apply in the
  execution domain.
- Review states for preparation, staleness, retry after confirmed rollback,
  manual recovery, and discard.
- Flow history and Run Review in one mission surface. The review shows exact
  changes, plan dependencies, permission profile, enforcement receipt, package
  digest, and Apply attempt history.
- Cursor-based Desktop change catch-up plus immediate mutation events.
- A 52-second Remotion product demo with current Desktop captures, no burned
  subtitles, and separate transcript/SRT publishing files. The checked-in SRT
  is provisional until retimed against the approved continuous narration.

## [changed]

- Orbit and Galaxy now stage one immutable package for one execution domain and
  one repository root. Apply never rebuilds the reviewed change set from live
  agent workspaces.
- Apply validates only affected-path preimages, so unrelated dirty checkout
  files do not invalidate a review. Drift on an affected path marks the review
  stale and requires a new package.
- Eligible workspaces remain available until dependent waves finish and the
  review package is durably written.
- Flow is the Desktop home for mission composition, active state, history, and
  completed-run review. Legacy Runs links redirect into Flow.
- The legacy Deck is excluded from the normal production startup path and
  remains available only through explicit development flags.
- Public product copy now describes the exact single-root Apply boundary and
  labels advisory host controls as advisory.

## [fixed]

- Run Review includes untracked additions and handles Git worktrees and
  copy-layer workspaces through the same package format.
- Preparation rejects traversal, protected `.git`/`.pytxo` paths, symlinks,
  sockets, FIFOs, devices, non-regular targets, and divergent ownership.
- A confirmed rollback returns the existing package to `ready`; ambiguous
  evidence stops mutation in `recovery_required`.
- Structured run finalization settles execution, persistence, billing,
  cancellation, and preparation failures and clears only the matching active
  run marker.
- Desktop prevents double Apply, explains unavailable actions, traps focus in
  discard confirmation, announces state changes, and respects reduced motion.

## Known limits

- Reviewed Apply is available only to Orbit and Galaxy in one repository root.
  DeepSpace is non-flushable. Supernova writes directly to the host tree and
  has no reviewed Apply step.
- v1.1 does not provide a cross-root transaction or partial-file acceptance.
- The journal supports automatic process-crash recovery. It is not a
  power-loss ACID or cross-filesystem durability guarantee.
- Orbit and Galaxy host process/network controls may be advisory where the OS
  cannot provide the requested kernel boundary. The enforcement receipt shows
  the status of each surface.
- The silent demo master is validated. The narrated master remains blocked
  until the approved ElevenLabs voice, Pixabay music certificate, and three
  licensed interface cues are present and reviewed.
- Desktop installers are unsigned unless the release workflow is run with
  validated Apple/Windows signing credentials; the updater manifest remains
  limited to builds signed with `TAURI_SIGNING_PRIVATE_KEY`.
- Source metadata and release notes do not publish installers, a tag, the
  website, or the demo. Those steps remain part of the release workflow.
