# Pytxo v1.3.5

`pytxo land` no longer blames a combination on one flaky check run, and
Desktop Work can pick which account one run uses.

These are prepared release notes, updated October 22, 2026, not a release
announcement.

## [added]

- **Account for one run.** When a CLI on the job has more than one sign-in,
  the Work composer shows an account select for it, starting at the account
  selected in Setup. Review shows the account on each task, saving a reviewed
  plan refuses changed accounts, and every task launches with its reviewed
  account. A missing account folder blocks the plan before anything starts.
  At launch, an `account` pinned in `pytxo.toml` still wins, then the run's
  reviewed account, then Setup's selected account, then `default`. Picking an
  account other than Setup's makes that CLI ready only when that account is
  signed in.

## [fixed]

- **Flaky combined checks.** With `--per-input`, when every branch passed a
  check alone but the combined change failed it, `pytxo land` blamed the
  combination after one run. A flaky test could make it report a combined
  failure that a plain merge did not have. It now runs that check on the
  combination once more:
  - fails again: blocked, with `combined check failed twice` and "The
    combined change failed both times it ran";
  - passes: still blocked, with `combined check flaky`, and the combination
    is not blamed.

  The receipt records both runs; the second has `"rerun": true`. The field is
  omitted when false, so receipts from earlier versions read and verify
  unchanged. Text and Markdown output label the second run `combined, run 2`.
  Without `--per-input`, the check runs once, as before.

## Scope

`pytxo land` combined checks, receipts and Desktop Work and Review. Apply,
verification states, permission profiles and execution domains are unchanged:
the account choice only selects which vendor config folder the launch uses,
and the profile's environment policy still runs after it. The GitHub Action
defaults to installing 1.3.5.

## Install

```bash
npm i -g pytxo@1.3.5
pytxo --version
```
