# Pytxo v1.2.0

Pytxo v1.2.0 is the user-visible Desktop information-architecture break and the
evidence-ledger website. The reviewed Apply contract is unchanged: Orbit or
Galaxy, one execution domain, one repository root, journaled Apply of the
prepared package only.

## [changed]

- Desktop destinations are **Work**, **History**, and **Setup**. Workspace lives
  in the title bar. Approvals are an overlay. Hash aliases (`#/operations`,
  `#/missions`, `#/approvals`, `#/flow`, `#/integrations`, `#/runs`,
  `#/topology-focus`, `#/run-review`) still resolve.
- Work shows the run ledger by wave and the commit boundary with its
  enforcement receipt. History keeps every run with its outcome and Apply
  state. Setup holds Providers, Workspaces, Agents, Appearance, Keyboard,
  Voice, Privacy, and Account.
- Rendered product state uses the epistemic contract: verified, claimed,
  unknown, or refuted, with attention as a cue — not a fifth state. Fill and
  hue are not treated as proof.
- pytxo.com is a seven-section narrative with one large Work capture, a real
  ADE registry grid, `/evidence`, and honest platform availability on
  `/download`.
- Aligned Rust CLI, npm CLI wrapper, Desktop package, and installer metadata
  on version 1.2.0, with a release-time parity check.

## Scope

This minor does not broaden reviewed Apply. It remains limited to Orbit and
Galaxy, one execution domain, and one repository root. Pytxo applies only the
prepared package and reconciles process interruptions through its local
journal.

## Install

```bash
npm i -g pytxo@1.2.0
pytxo doctor
```

Windows CLI and Desktop artifacts:

- https://github.com/Pytxo-dev/pytxo-releases/releases/tag/v1.2.0

Desktop is Windows-first. The GitHub-hosted macOS/Linux Desktop matrix may
still be account/billing-blocked. If those jobs fail, only a fresh Windows
Desktop installer is claimed as v1.2.0. Do not treat older macOS or Linux
Desktop artifacts as 1.2.0 builds. CLI binaries still target five OS/arch
combinations when the CLI jobs succeed.

## Upgrade notes

- `ONBOARDING_VERSION` remains `1.1.0`, so existing Desktop users are not
  forced through the wizard again.
- Desktop opens to **Work**, not Ops.
- Orbit still requires human approval before applying changes.
- Vendor sessions and direct API credentials remain separate.
