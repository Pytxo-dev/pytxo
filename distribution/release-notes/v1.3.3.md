# Pytxo v1.3.3

Several sign-ins per agent CLI. Keep a work and a personal Claude Code or
Codex account side by side and pick which one new work uses. This release also
stops a worker that failed quietly from showing as passed.

These are prepared release notes, updated October 19, 2026, not a release
announcement.

## [added]

- **Accounts per agent CLI.** `pytxo accounts list|add|login|use|remove`
  manages more than one sign-in for Claude Code and Codex. Each account is the
  CLI's own config folder under `~/.pytxo/agent-accounts/<cli>/<name>/`,
  selected for each launch through the variable the vendor documents
  (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`). Sign-in runs the vendor's own command;
  Pytxo never reads or copies the credentials it writes. `default` is the
  CLI's usual sign-in.
- **Which account runs.** An agent in `pytxo.toml` can pin one with
  `account = "work"`; otherwise new work uses the account selected for that
  CLI, then `default`. The run log records the account name (never its path),
  a missing account is refused before the agent starts, and when a worker
  fails on an expired login or a usage limit Pytxo names the account.
- **Desktop Setup.** Setup → Agents & permissions → Agent CLIs lists the
  accounts for each supported CLI with their sign-in state, and the CLI's
  readiness follows the selected account.

Pytxo never switches accounts on its own when one reports a limit. Every
account must be yours: provider terms forbid sharing accounts and working
around usage limits. Cursor Agent, Antigravity and Gemini CLI keep one sign-in
per OS user, so they have no accounts list.

## [fixed]

- **Quiet failures no longer pass.** Some agent CLIs exit 0 after printing an
  error, for example `opencode run` with `Error: Model not found` when its
  provider has no stored credential. The task's checks then passed on the
  untouched worktree. A zero exit now counts as failed when the last output
  line is a CLI error and none of the task's paths changed: checks are
  skipped, dependent tasks are blocked and the real exit code is kept. This
  applies under DeepSpace, Orbit and Galaxy; Supernova runs in the repository
  root and is unchanged.
- **Log redaction.** Logs and MCP payloads now redact Anthropic API keys and
  Claude OAuth tokens (`sk-ant-…`), bare JWTs and JSON `access_token`,
  `refresh_token` and `id_token` values. Windows profile paths are redacted in
  full; the old rule stopped at the first `s` in a user name.

## Scope

Agent launch, the CLI, Desktop Setup and log redaction. Review, Apply,
verification states, permission profiles and execution domains are unchanged.
The GitHub Action defaults to installing 1.3.3.

## Install

```bash
npm i -g pytxo@1.3.3
pytxo --version
```
